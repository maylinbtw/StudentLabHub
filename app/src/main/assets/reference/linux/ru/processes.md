# Процессы

**Процесс** — запущенная программа. У каждого процесса есть номер **PID**, владелец и родительский процесс, который его запустил.

## ps — список процессов

```bash
ps                           # процессы текущего терминала
ps aux                       # все процессы системы
ps aux | grep firefox        # найти нужный
ps -ef --forest              # дерево: кто кого запустил
pgrep -l java                # PID процессов по имени
```

Основные столбцы `ps aux`:

| Столбец | Значение |
|---|---|
| `USER` | владелец процесса |
| `PID` | номер процесса |
| `%CPU`, `%MEM` | загрузка процессора и памяти |
| `STAT` | состояние: `R` — работает, `S` — ждёт, `Z` — зомби |
| `COMMAND` | команда запуска |

## top и htop — монитор в реальном времени

```bash
top                          # встроенный монитор
htop                         # удобнее: цвета, мышь, прокрутка
```

Клавиши в `top`: `P` — сортировать по процессору, `M` — по памяти, `k` — завершить процесс, `q` — выход.

## Сигналы и завершение процессов

Процессу можно отправить **сигнал**. Чаще всего — чтобы завершить его:

```bash
kill 4321                    # вежливо попросить завершиться (SIGTERM)
kill -9 4321                 # убить немедленно (SIGKILL)
killall firefox              # все процессы с таким именем
pkill -f "python bot.py"     # по части командной строки
```

| Сигнал | Номер | Что делает |
|---|---|---|
| `SIGTERM` | 15 | просьба завершиться, программа может сохранить данные |
| `SIGKILL` | 9 | немедленное завершение, перехватить нельзя |
| `SIGINT` | 2 | то же, что `Ctrl+C` |
| `SIGHUP` | 1 | терминал закрыт; многие службы так перечитывают настройки |

> Сначала пробуйте обычный `kill`. `kill -9` — крайняя мера: программа не успеет сохранить файлы и освободить ресурсы.

## Фоновые задачи

```bash
./server &                   # запустить в фоне, терминал свободен
jobs                         # список фоновых задач терминала
fg %1                        # вернуть задачу 1 на передний план
```

Если программа уже запущена: `Ctrl+Z` приостанавливает её, `bg` продолжает выполнение в фоне.

Фоновая задача завершится вместе с терминалом. Чтобы она продолжала работать после выхода:

```bash
nohup ./server > server.log 2>&1 &
```

## Службы systemd

Серверы и фоновые службы в большинстве дистрибутивов управляются через `systemctl`:

```bash
systemctl status ssh         # состояние службы
sudo systemctl start ssh     # запустить
sudo systemctl stop ssh      # остановить
sudo systemctl restart ssh   # перезапустить
sudo systemctl enable ssh    # запускать при загрузке системы
journalctl -u ssh -f         # журнал службы в реальном времени
```

## Ресурсы системы

```bash
free -h                      # оперативная память
uptime                       # время работы и средняя нагрузка
nproc                        # число ядер процессора
```
