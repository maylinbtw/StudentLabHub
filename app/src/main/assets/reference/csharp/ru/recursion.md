# Рекурсия

**Рекурсия** — когда метод вызывает сам себя. Задача сводится к такой же, но меньшей задаче, пока не дойдёт до простого случая.

## Базовый случай и шаг

У рекурсивного метода всегда две части:

- **базовый случай** — условие, при котором метод возвращает ответ без нового вызова;
- **рекурсивный шаг** — вызов себя с аргументом, который ближе к базовому случаю.

## Факториал

`n! = n × (n − 1)!`, а `0! = 1`:

```csharp
static long Factorial(int n)
{
    if (n <= 1) return 1;          // базовый случай
    return n * Factorial(n - 1);   // рекурсивный шаг
}

Console.WriteLine(Factorial(5));
```

```output
120
```

Как идёт вычисление:

```text
Factorial(5) = 5 * Factorial(4)
             = 5 * 4 * Factorial(3)
             = 5 * 4 * 3 * Factorial(2)
             = 5 * 4 * 3 * 2 * Factorial(1)
             = 5 * 4 * 3 * 2 * 1
             = 120
```

## Сумма цифр числа

```csharp
static int DigitSum(int n)
{
    if (n < 10) return n;
    return n % 10 + DigitSum(n / 10);
}

Console.WriteLine(DigitSum(4096)); // 19
```

## Стек вызовов

Каждый вызов метода занимает место в **стеке вызовов**: там хранятся его параметры и локальные переменные. Вызов освобождает место, только когда завершится.

> [!WARNING]
> Если базового случая нет или он недостижим, вызовы идут бесконечно, стек переполняется и программа падает с `StackOverflowException`. Это исключение нельзя перехватить через `try/catch`.

```csharp
static int Broken(int n) => Broken(n - 1); // нет базового случая
```

## Числа Фибоначчи

Каждое число равно сумме двух предыдущих: 0, 1, 1, 2, 3, 5, 8…

```csharp
static long Fib(int n)
{
    if (n < 2) return n;
    return Fib(n - 1) + Fib(n - 2);
}
```

Код короткий, но медленный: `Fib(n - 2)` считается повторно внутри `Fib(n - 1)`, и число вызовов растёт экспоненциально. `Fib(45)` будет работать несколько секунд.

Тот же результат циклом считается мгновенно:

```csharp
static long FibLoop(int n)
{
    long a = 0, b = 1;
    for (int i = 0; i < n; i++)
        (a, b) = (b, a + b);
    return a;
}
```

## Когда использовать рекурсию

| Подходит | Лучше цикл |
|---|---|
| обход деревьев и вложенных папок | простой счётчик, перебор массива |
| «разделяй и властвуй»: быстрая сортировка, бинарный поиск | большая глубина вызовов (тысячи и больше) |
| задачи, которые естественно описываются через себя | повторные вычисления одного и того же |

Пример, где рекурсия удобна, — подсчёт файлов во всех вложенных папках:

```csharp
static int CountFiles(string path)
{
    int count = Directory.GetFiles(path).Length;
    foreach (string dir in Directory.GetDirectories(path))
        count += CountFiles(dir);
    return count;
}
```

## Проверь себя

> [!QUIZ]
> Что произойдёт с рекурсивным методом без базового случая?
> ---
> Вызовы пойдут бесконечно, стек переполнится, и программа упадёт со `StackOverflowException`.

> [!QUIZ]
> Почему рекурсивный `Fib(n)` работает медленно?
> ---
> Одни и те же значения считаются много раз, и число вызовов растёт экспоненциально. Цикл считает за линейное время.
